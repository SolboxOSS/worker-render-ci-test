# 정책 예외 기록

자동 게이트(라이선스·취약점)를 통과하지 못한 항목을 승인 하에 예외 처리한 기록이다.
예외에는 반드시 **승인자와 만료일**이 있어야 하며, 만료일이 지나면 재검토한다. (가이드라인 1장·3장 7절)

- CI의 취약점 게이트(`scripts/supply-chain/vuln_gate.py`)가 이 표를 읽는다. **상태가 `유효`이고 승인자가 있으며 만료일이 지나지 않은 행**의 `식별자`만 통과시킨다.
- 만료일이 지나면 자동으로 다시 차단된다. 연장하려면 재검토 후 만료일을 고친다.
- 예외번호는 사내 위키 「6. 예외 승인대장」의 번호와 같게 쓴다.

## 식별자 작성 규칙 (미조치 취약점 비공개)

예외 목록은 "알고도 배포하는 취약점"이므로 **공개 저장소에는 CVE 번호를 적지 않는다.**

- **공개 저장소**: `식별자`에 지문(`h:` + 16자리)을 적는다. CVE 평문 행은 게이트가 인정하지 않는다.
  ```bash
  EXCEPTION_KEY=<저장소 Secret과 같은 값> python3 scripts/supply-chain/vuln_gate.py --fingerprint CVE-2026-12345
  # CVE-2026-12345  h:1a2b3c4d5e6f7a8b
  ```
  지문은 저장소 Secret `EXCEPTION_KEY` 없이는 CVE로 되돌릴 수 없다.
- **비공개 저장소**: CVE 번호를 그대로 적어도 된다(지문도 사용 가능).
- `대상`에는 구성요소 이름만 적고 버전·완화조치 상세는 적지 않는다.
- **예외번호 ↔ CVE 대응과 완화조치 상세는 사내 위키 「6. 예외 승인대장」에만 둔다.**

| 예외번호 | 식별자 | 대상 (구성요소) | 유형 | 완화조치 | 승인자 | 승인일 | 만료일 | 상태 |
|---|---|---|---|---|---|---|---|---|
| EX-0000 | (예) h:0000000000000000 | (예) libfoo | 취약점 | 위키 예외 승인대장 참조 | (이름) | 2026-10-20 | 2027-01-20 | 예시 |
